# 一括取得の指示改善と採用結果

2026-10-16。**耐久実行を通常利用に接続し、取得は一括方式へ整理した。人物・否定・例外の指示変更も、事前の採用基準を満たしたため採用する。**

## 変更の順序

1. `bun run memory` を通常利用の入口に追加し、既存の `planMemory` と `applyMemoryPlan` を接続。計画では書き込まず、保存した計画と操作IDで適用・再試行する。失敗を成功終了に変えない。部分・結合16テスト、全体518テストを通してコミット。
2. `recallMemory` / `recallSnapshot` を全許可記憶の一回入力へ変更。候補選択とページ予算を通常経路から除去し、旧方式は実験用の凍結版へ移した。1001件の全件入力、人物ラベル・極性・忘却後の除外・許可ID検査を確認。部分・結合20テスト、全体522テストを通してコミット。
3. 一括取得の指示だけを変更。以下の新規100件・既知回帰20件で旧新を比較。実行ロジック、モデル、スキーマ、各ケースの入力と正解は同じ。

保存・忘却の意味判断は既存の計画指示を使い、今回の追加改善は取得側の指示に限定した。人物や否定語を検出する専用分岐・辞書・正規表現は製品コードに追加していない。入力上限や通信の失敗は例外となり、黙って記憶を切り捨てたり成功した不明回答に変えたりしない。

## 何が改善し、何が残ったか

本人と他人の肯定・否定を混ぜて矛盾と扱う失敗、否定された事実一つを矛盾扱いする失敗、異なる期間の主張や適用可能な例外を矛盾扱いする失敗が減った。必要条件をそろえた判断、条件不明時の不明回答、質問の分割にも改善があった。

## 使い方と再現

```sh
bun run memory /tmp/my-memory plan '休日に銀細工を楽しんでいます。覚えてください。' > /tmp/plan.json
bun run memory /tmp/my-memory apply request-001 /tmp/plan.json
bun run memory /tmp/my-memory recall '休日に楽しんでいることは？'
```

再試行は同じ操作IDと同じ保存済み計画を `apply` へ渡す。実行途中に計画を作り直さない。`needs_clarification` は全変更の成功を意味しない。人物カタログを持つホストは `planMemory` と `recallMemory` の `subjects` 引数を使う。

今回の再集計:

```sh
bun examples/experiments/one-shot-holdout/analyze.ts verification-reports/one-shot-holdout/design.json verification-reports/one-shot-holdout/run verification-reports/one-shot-holdout/summary.json verification-reports/one-shot-holdout/frozen-generator.ts verification-reports/one-shot-holdout/recovery
```

再実行はfreeze.tsで新しい設計ファイルを作り、run.tsへ新しい出力先を渡す。凍結時刻が変わるため設計ハッシュは今回と異なる。凍結後の実行器・採点器・指示変更は拒否する。

比較完了後、freeze.tsの旧新文字列の一致検査を `String(before) === String(after)` へ変更した。異なる文字列リテラル型の比較に対する型エラーを解消する、同値な変更である。試験時の原文はfrozen-generator.tsに保存して照合し、生成入力・モデル指示・実行器・採点器は変更していない。
