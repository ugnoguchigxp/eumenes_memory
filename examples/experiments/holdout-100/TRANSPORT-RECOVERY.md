# 通信失敗のみの補完規則（補完開始前）

修正版取得試験の実行中、一部の呼出しが HTTP 403 で応答を取得できなかった。その後、同じ接続設定で多数の応答取得が成功している。認証・権限を変更せず、100ケースの投入終了後に並行数を8から1へ下げ、未取得応答だけを1回補完する。

`recover-retrieval.ts` は元の報告を変更しない。成功済み呼出しはステージ・入力・スキーマのハッシュが一致する保存応答をそのまま再生する。採点不合格・形式不正など応答を取得済みの失敗を引き直さない。未取得応答と、その失敗のため未実行だった後続呼出しだけを実行する。補完中にも通信失敗が起きた場合は停止し、その記録を残す。

出力先は `retrieval-v2-recovery/`。元報告と元行のハッシュ、既存呼出し、新規呼出し、元エラーを保存する。集計時に元の成功応答が変わっていないことを検査する。時間は元の実行時間に補完実行時間を加算する（バッチ終了を待った時間は含めない）。失敗呼出しの使用量はサービスから返らないため不明と記録し、ゼロと断定しない。成功済み応答の再生は実呼出しにも使用量にも二重計上しない。
