# 入力・根拠表現の単純化：事前登録

2026-10-16。基準 c265833。目的は指示の増量や意味判断の専用コードを使わず、残る否定・関係・実在する誤った根拠の選択を改善すること。

## 仮説と範囲

現行は長い itemId、semanticKey、revision を含む保存表現を渡す。命題本文と polarity が離れている。候補は読み取り専用の機械的投影で、(1) itemId を入力順の短い文字列番号へ置換、(2) 更新用 semanticKey と revision を省略、(3) value を statement: {affirmed: 原文} または {negated: 原文} にする。subject、subjectLabel、kind、適用期間と validity、原文、順序、件数はそのまま。肯定・否定についての既存指示を新フィールド名に置換し、増量しない。

候補は一つの表現変更として評価する。3要素それぞれの独立効果は測らない。根拠の原文コピー追加は出力増加と照合処理が必要、ID列挙スキーマだけでは実在する誤IDを防げないため今回採らない。別のLLMによる前処理、意味的な文変換、意味分類、専用分岐は追加しない。DB・公開API・書込み・実行機構は範囲外。全記憶を一回で渡す現行取得方式を維持する。

根拠は共通 parseEvidence でその回の番号との完全一致・重複・status 契約を検証した後、対応する元IDへ写す。誤った実在番号を選べば誤答として採点する。補正・曖昧一致・選び直しはしない。元の snapshotHash は元の全入力から計算する。

## ケースと固定採点

新規100件＝25分野各4件。否定の作用域、決定・知識・義務・発言、関係の欠落と向きと多段連結、同名異人、条件・例外、訂正・時間、部分回答・衝突、近似属性と根拠番号、興味、入力内指示等。8/24/64/256/1001件の記憶を各20問。問題ごとの主要事実と正解は個別に執筆し、無関係記憶と配置は決定的生成。新しい自然文の問題だが既知の失敗構造も含む合成ベンチマークであり、未知分布の実会話を保証しない。

回帰320件＝最初の holdout 100、最初の回帰20、前回 A100、B100。既存入力・順序・正解を変更しない。過去に期待根拠が厳しいケースも既存goldを維持し、解釈上の制約は結果で明記する。質問の完全一致重複は検査するが意味上の独立性までは保証しない。

採点は既存 score.ts をそのまま使う。質問順の回答部分数・status・必須根拠集合・許容根拠集合がすべて一致した時だけ1問正解。部分点は主指標にしない。対象外の実在ID、必要な関係根拠の欠落、unknownの過剰回答も不正解。自然文の回答内容は出力契約にないため正確性を評価できない。

## 実行と採用条件

両側 gpt-6-luna / medium、1回答、同一の根本事実・出力schema・共通ランタイム。入力表現のみ異なるので各側の実際の入力hashを個別検証。モデルへの指示全文、schema、設計・実行・採点コードのhashを固定してコミットした後に実行。4並列、ケース順に両側の先後を交替。合計840回答。検証中は固定ソースを編集しない。

全回答取得を前提に以下をすべて満たせば採用候補とする。

- 新規の正解数差 >= +5 /100。
- 25分野の正解数増加/減少を単位とした片側符号検定 p <= .05（今回一案）。同点分野は除く。
- 回帰320件の正解数差 >= 0。
- 新規・回帰それぞれ、入力+出力トークン比 <= 1.10、中央値時間比 <= 1.25。

これは統計的な非劣性保証ではない。採用条件に加え、全勝敗・両側失敗でも誤りが変わったケースを点検し重大な新規誤動作は採用しない。出力形式不正・無効IDと、形式が通る誤った実在IDは区別する。分野・入力サイズ別、入力/出力/キャッシュトークン、中央値/p95、呼び出し回数とエラーを報告。通貨額は価格を仮定せず、トークンの実測をコスト比較とする。

返答取得後の意味的再試行はしない。SDK呼出しの連続3通信失敗で新規送信停止。全420ペアの初回終了後、出力のない HTTP403 だけ各1回回復可。原失敗・所要時間を保存、消費量不明を明記し、回復でも失敗なら追加再試行しない。SDK内部の接続リトライは別途追跡不能。
